| Browser → Server Action createBarbershop | barbershop_id nunca aceito como parâmetro do cliente — sempre lido de getClaims() |
| Browser → JWT refresh | refreshSession() é chamado client-side após step 1 — nunca server-side em Server Actions |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-06 | Tampering | createBarbershop — duplicate row on refresh | mitigate | Idempotency guard: se barbershop_id já existe no JWT, retorna early sem INSERT |
| T-01-07 | Elevation of Privilege | working_hours INSERT — RLS via subquery | mitigate | upsertBarberWorkingHours recebe barberId mas RLS valida que barber.barbershop_id = JWT barbershop_id via subquery policy |
| T-01-08 | Tampering | Onboarding step skip — acessar step 4 sem step 1 | mitigate | Cada Server Action lê barbershop_id do JWT — sem barbershop_id, INSERT falha por RLS mesmo que UI pule passos |
</threat_model>
