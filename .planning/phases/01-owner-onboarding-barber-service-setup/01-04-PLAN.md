New code to add:

```
// Rule D — Owner without barbershop_id on /dashboard routes → redirect to /onboarding
// Note: /onboarding redirect to /dashboard (Rule E) only applies when barbershop_id IS present.
// The inverse (redirect /dashboard → /onboarding) applies to ALL /dashboard routes when missing.
const barbershop_id = claims?.app_metadata?.barbershop_id as string | undefined
if (isOwnerRoute && role === 'owner' && claims && !error && !barbershop_id) {
  return NextResponse.redirect(new URL('/onboarding', request.url))
}

// Rule E — Owner with barbershop_id trying to access /onboarding → redirect to /dashboard
// One-direction only — prevents loop: after step 1, old JWT may lack barbershop_id
// so we only redirect /onboarding → /dashboard when barbershop_id IS present in JWT.
const isOnboardingRoute = pathname.startsWith('/onboarding')
if (isOnboardingRoute && role === 'owner' && claims && !error && barbershop_id) {
  return NextResponse.redirect(new URL('/dashboard', request.url))
}
```

CRITICAL anti-loop rule: Do NOT add a guard that redirects /onboarding to /entrar for unauthenticated users — Rule A already handles unauthenticated access to all routes. Do NOT add the inverse Rule D (redirect /dashboard → /onboarding) in the same block that checks Rule E — they are separate conditions already preventing the loop.

The `barbershop_id` variable must be declared AFTER the existing `role` variable extraction (reuse the same `claims` object). Do not call getClaims() twice.

After editing, verify the file compiles by running: npm run build
