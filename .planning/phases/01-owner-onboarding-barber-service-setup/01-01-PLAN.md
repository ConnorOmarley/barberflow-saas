Create supabase/migrations/20260531000001_phase1_schema.sql with the following content (exact structure, do not simplify):

HEADER COMMENT: Follow the same 8-line block comment pattern from 20260529000001_initial_schema.sql, adapting the description.

TABLE ORDER (create in this order to respect FK dependencies):
1. public.barbers — with barbershop_id FK + profile_id NULL FK + all columns from D-06
2. public.services — with barbershop_id FK + columns from D-07
3. public.barber_services — junction table, (barber_id, service_id) PK + commission columns from D-08
4. public.working_hours — barber_id FK + TIME columns from D-09
5. public.appointments — all columns from D-10 including cancelled_by UUID REFERENCES auth.users(id)

RLS PATTERN — immediately after each CREATE TABLE, no gap:
- Tables WITH direct barbershop_id (barbers, services, appointments): use direct equality policy "tenant_<table>_all" USING/WITH CHECK barbershop_id = (auth.jwt() -> 'app_metadata' ->> 'barbershop_id')::UUID
- Tables WITHOUT barbershop_id (barber_services, working_hours): use subquery policy via barbers: barber_id IN (SELECT id FROM public.barbers WHERE barbershop_id = (auth.jwt() -> 'app_metadata' ->> 'barbershop_id')::UUID)

TRIGGER (after all tables):
Create function public.handle_invite_accepted() RETURNS TRIGGER LANGUAGE plpgsql SECURITY DEFINER SET search_path = '' that fires AFTER UPDATE ON auth.users FOR EACH ROW. Guard condition: OLD.encrypted_password IS NULL OR OLD.encrypted_password = '' AND NEW.encrypted_password IS NOT NULL AND NEW.encrypted_password != '' AND NEW.raw_user_meta_data ? 'barber_id'. Body: UPDATE public.barbers SET profile_id = NEW.id WHERE id = (NEW.raw_user_meta_data->>'barber_id')::UUID AND profile_id IS NULL.

SECURITY HARDENING (end of file, matching Phase 0 pattern):
ALTER FUNCTION public.handle_invite_accepted() SET search_path = '';
REVOKE EXECUTE ON FUNCTION public.handle_invite_accepted() FROM public, anon, authenticated;

STORAGE BUCKET (at end of migration, after all table DDL and triggers):
Create the barber-photos storage bucket with public=false so uploads cannot be accessed without auth:
  INSERT INTO storage.buckets (id, name, public) VALUES ('barber-photos', 'barber-photos', false) ON CONFLICT (id) DO NOTHING;
  -- Authenticated-only INSERT policy (per-tenant tightening deferred to Phase 8)
  CREATE POLICY "authenticated_insert_barber_photos" ON storage.objects
    FOR INSERT TO authenticated
    WITH CHECK (bucket_id = 'barber-photos');
  CREATE POLICY "authenticated_select_barber_photos" ON storage.objects
    FOR SELECT TO authenticated
    USING (bucket_id = 'barber-photos');

CRITICAL constraints:
- appointments.status DEFAULT 'CONFIRMED' CHECK (status IN ('PENDING','CONFIRMED','CHECKED_IN','COMPLETED','CANCELLED'))
- working_hours.day_of_week SMALLINT CHECK BETWEEN 0 AND 6
- barber_services.commission_type TEXT NULL CHECK (commission_type IN ('percent', 'fixed'))
- All TIMESTAMPTZ columns use DEFAULT NOW()
- NO exclusion constraint on appointments (added in Phase 2 only)
- appointments.booking_source TEXT NULL (no CHECK constraint needed here)
