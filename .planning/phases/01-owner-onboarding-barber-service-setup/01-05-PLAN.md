<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| BarberDrawer (browser) → createBarber Server Action | barbershop_id nunca aceito como parâmetro do form; sempre lido de getClaims() no servidor |
| BarberDrawer (browser) → Supabase Storage | Upload usa anon key + RLS de storage — bucket barber-photos com authenticated INSERT policy |
| inviteBarber Server Action → Admin Client | createAdminClient() usada APENAS no inviteBarber; import isolado; nunca no client |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-12 | Tampering | barber photo upload — path traversal | mitigate | Path = ${barberId}/${Date.now()}.${ext}; barberId é UUID do DB, não user input; ext extraído do filename sem path traversal |
| T-01-13 | Information Disclosure | inviteBarber — email validation | mitigate | inviteUserByEmail enviado apenas para email fornecido pelo owner; barbershop_id do JWT (não do form); error message não vaza internal state |
| T-01-14 | Tampering | syncBarberServices — cross-tenant | mitigate | DELETE WHERE barber_id = ? + RLS subquery via barbers.barbershop_id garante que owner só altera barbers do seu tenant |
</threat_model>
