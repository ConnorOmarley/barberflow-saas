SEÇÃO 1 — Helpers de timezone (funções locais, não exportadas):

1. `getUTCOffset(dateStr: string, timezone: string): string`
   Retorna offset como '-03:00' ou '+00:00'. Usa `Intl.DateTimeFormat` com `timeZoneName: 'longOffset'`. Extrai de 'GMT-03:00' → '-03:00'.

2. `getLocalDayOfWeek(dateStr: string, timezone: string): number`
   Retorna 0 (Dom) a 6 (Sáb). Usa `Intl.DateTimeFormat` com `timeZone` e `weekday: 'short'` em 'en-US'. Mapa: Sun=0, Mon=1, Tue=2, Wed=3, Thu=4, Fri=5, Sat=6.
   Usar `new Date(dateStr + 'T12:00:00Z')` para evitar edge cases de DST.

3. `localDateToUTCStart(dateStr: string, timezone: string): string`
   Retorna `new Date(dateStr + 'T00:00:00' + getUTCOffset(dateStr, timezone)).toISOString()`

4. `localDateToUTCEnd(dateStr: string, timezone: string): string`
   Retorna `new Date(dateStr + 'T23:59:59' + getUTCOffset(dateStr, timezone)).toISOString()`

SEÇÃO 2 — `getAvailableSlots`:

Importar: createPublicClient de '@/lib/supabase/public'. Receber input tipado. Envolver em try/catch com retorno `{ error: err.message }`.

Passos em ordem:
1. Resolver barbershop pelo slug para obter `id` e `timezone`. Se não encontrar → return { error }
2. Calcular `dayIndex` via `getLocalDayOfWeek(input.date, barbershop.timezone)`
3. Buscar `working_hours` do barbeiro para `day_of_week = dayIndex AND is_active = true`
4. Se vazio → return { slots: [] }
5. Buscar `service.duration_minutes` pelo `input.service_id`. Se não encontrar → return { error }
6. Buscar `appointments` do barbeiro no dia (UTC range via `localDateToUTCStart`/`End`), WHERE `status != 'CANCELLED'`, SELECT `start_time, end_time` apenas
7. Para cada janela de working_hours:
   - Construir `whStartUTC` e `whEndUTC` usando `new Date(dateStr + 'T' + wh.start_time + offset).getTime()`
   - Loop: `cursor = whStartUTC`, incrementar por `slotInterval * 60_000` (slotInterval = 30 min)
   - Enquanto `cursor + duration * 60_000 <= whEndUTC`: verificar se há overlap com appointments existentes. Se não houver, adicionar `new Date(cursor).toISOString()` ao array de slots
   - Overlap check: `slotStart < apptEnd && slotEnd > apptStart`
8. Return { slots }

`const slotInterval = 30` — granularidade fixa de 30 minutos.

SEÇÃO 3 — `createPublicAppointment`:

Importar: createPublicClient, createAdminClient, revalidatePath.

Envolver TUDO em try/catch. Nunca lançar exceção — sempre retornar { error }.

Passos em ordem:
1. `createPublicClient()` → resolver barbershop pelo slug → obter `id`. Se falhar → return { error }
2. `createPublicClient()` → buscar `services.duration_minutes` pelo `input.service_id`. Se falhar → return { error }
3. Calcular `endTime = new Date(new Date(input.start_time).getTime() + duration * 60_000).toISOString()`
4. Normalizar WhatsApp: remover não-dígitos; se começar com '55' e len >= 12 → '+' + digits; se len >= 10 → '+55' + digits
5. `createAdminClient()` → upsert em `clients` com `onConflict: 'barbershop_id,whatsapp_number'`, `ignoreDuplicates: false`. Campos: barbershop_id, full_name, whatsapp_number (normalizado), whatsapp_opt_in, opt_in_source (se opt_in=true: 'booking_portal', else null), opt_in_timestamp (se opt_in=true: new Date().toISOString(), else null). Select `id`. Se erro → return { error }
6. `createPublicClient()` → app-layer conflict check: SELECT id FROM appointments WHERE barber_id = ? AND status != 'CANCELLED' AND start_time < endTime AND end_time > start_time LIMIT 1. Se conflito → return { error: 'Horário indisponível. Escolha outro horário.' }
7. `createAdminClient()` → INSERT em `appointments`: { barbershop_id: barbershop.id, barber_id: input.barber_id, service_id: input.service_id, client_id: client.id, start_time: input.start_time, end_time: endTime, status: 'PENDING', booking_source: 'portal', created_by: null }. Select `id, start_time`.
8. Se insertError: se `insertError.code === '23P01'` → return { error: 'Horário indisponível. Escolha outro horário.' }. Outros erros → return { error: insertError.message }
9. revalidatePath('/dashboard'). Return { data: appointment }

<threat_model>
## Trust Boundaries

| Boundary | Descrição |
|----------|-----------|
| cliente browser → createPublicAppointment | Entrada não confiável: slug, service_id, barber_id, start_time, dados do cliente |
| Server Action → Supabase admin | Writes usam service role — bypassa RLS; barbershop_id NUNCA vem do cliente |
| Server Action → exclusion constraint | DB é a última linha de defesa contra race conditions |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-09 | Tampering | createPublicAppointment — barbershop_id | mitigate | barbershop_id resolvido exclusivamente via slug server-side; parâmetro `barbershop_id` não existe na interface de entrada |
| T-02-10 | Tampering | createPublicAppointment — end_time | mitigate | duration_minutes lido do DB server-side via service_id; cliente passa apenas start_time; end_time calculado server-side |
| T-02-11 | Denial of Service | createPublicAppointment — flooding | accept | Rate limiting fora do escopo MVP; Supabase tem rate limit básico por IP na camada anon |
| T-02-12 | Repudiation | whatsapp_opt_in sem consent real | mitigate | Checkbox explícito no step-client com default false; opt_in_timestamp gravado server-side (não vem do cliente); opt_in_source = 'booking_portal' documenta origem |
| T-02-13 | Tampering | getAvailableSlots — slot manipulation | mitigate | Slots são apenas strings ISO sugeridas pela UI; createPublicAppointment valida independentemente no servidor via conflict check + exclusion constraint |
| T-02-14 | Information Disclosure | getAvailableSlots — appointments query | mitigate | Query seleciona apenas start_time, end_time — nunca client_id, notes ou dados pessoais |
| T-02-15 | Tampering | Race condition double-booking | mitigate | App-layer conflict check (defesa complementar) + exclusion constraint GIST (garantia real) — código 23P01 capturado e retornado como erro amigável |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | Nenhum pacote novo — usa shadcn/ui, RHF, Zod, @supabase já instalados |
</threat_model>
