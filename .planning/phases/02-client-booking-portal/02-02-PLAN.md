ARQUIVO 1 — `src/lib/supabase/public.ts`:

Criar conforme padrão documentado em 02-PATTERNS.md e 02-RESEARCH.md (Decisão 4). Estrutura idêntica a `src/lib/supabase/admin.ts` mas usando `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (anon key) em vez da service role key:

```
import { createClient as createSupabaseClient } from '@supabase/supabase-js'
import type { Database } from '@/types/database.types'

export function createPublicClient() {
  return createSupabaseClient<Database>(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY!,
    {
      auth: {
        autoRefreshToken: false,
        persistSession: false,
      },
    }
  )
}
```

ARQUIVO 2 — `src/middleware.ts` (modificar):

Adicionar bypass para rotas públicas. POSIÇÃO CRÍTICA: inserir ANTES da linha `const supabase = createServerClient(...)` (ou equivalente), usando `request.nextUrl.pathname` diretamente — NÃO após `const pathname`, que no middleware atual é declarado depois do getClaims(). Isso evita que o Supabase client seja inicializado desnecessariamente para rotas públicas:

```typescript
// Bypass para portal público — DEVE ser a PRIMEIRA coisa no corpo da função,
// usando request.nextUrl.pathname diretamente (não a variável `pathname` que
// só existe mais abaixo no middleware, após getClaims).
const _pubPathname = request.nextUrl.pathname
const reservedPaths = ['/entrar', '/cadastro', '/dashboard', '/agenda', '/onboarding', '/auth', '/_next', '/api']
const isReserved = reservedPaths.some(p => _pubPathname.startsWith(p))
const isPublicSlug = !isReserved && /^\/[a-z0-9][a-z0-9-]*($|\/.*)$/.test(_pubPathname)
if (isPublicSlug) return NextResponse.next()
```

Esta lógica:
- Deve ser inserida antes de `const supabase = createServerClient(...)` — evita inicializar o Supabase client para rotas públicas
- Não interfere com rotas de auth existentes
- Permite /[slug], /[slug]/booking e qualquer subrota
- Retorna `NextResponse.next()` — passa sem verificação de auth
