Create src/middleware.ts (at the src/ level, which is the Next.js 15 project root when --src-dir is used).

The middleware must implement:

IMPORTS:
  import { createServerClient, parseCookieHeader } from '@supabase/ssr'
  import { NextResponse, type NextRequest } from 'next/server'

FUNCTION: export async function middleware(request: NextRequest)

STEP 1 — Create response object:
  let response = NextResponse.next({ request: { headers: request.headers } })

STEP 2 — Create Supabase client using parseCookieHeader (middleware cannot use cookies() from next/headers):
  const supabase = createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY!,
    {
      cookies: {
        getAll() { return parseCookieHeader(request.headers.get('cookie') ?? '') },
        setAll(cookiesToSet) {
          cookiesToSet.forEach(({ name, value }) => response.cookies.set(name, value))
        },
      },
    }
  )

STEP 3 — Get JWT claims using getClaims() (NEVER getSession()):
  const { data, error } = await supabase.auth.getClaims()
  const claims = data?.claims
  const role = claims?.app_metadata?.role as string | undefined
  const pathname = request.nextUrl.pathname

STEP 4 — Route protection rules (apply in this order):
  Rule A — Unauthenticated access to protected routes → redirect to /entrar:
    const isOwnerRoute = pathname.startsWith('/dashboard')
    const isBarberRoute = pathname.startsWith('/agenda')
    if ((isOwnerRoute || isBarberRoute) && (!claims || error)) {
      return NextResponse.redirect(new URL('/entrar', request.url))
    }

  Rule B — Authenticated user accessing auth pages → redirect to their dashboard:
    const isAuthPage = pathname === '/entrar' || pathname === '/cadastro'
    if (isAuthPage && claims && !error) {
      const redirectTo = role === 'barber' ? '/agenda' : '/dashboard'
      return NextResponse.redirect(new URL(redirectTo, request.url))
    }

  Rule C — Role mismatch: barber on owner route → redirect to /agenda:
    if (isOwnerRoute && role === 'barber') {
      return NextResponse.redirect(new URL('/agenda', request.url))
    }

STEP 5 — Return response (with refreshed session cookie set):
  return response

MATCHER CONFIG (CRITICAL — prevents middleware running on static files):
  export const config = {
    matcher: ['/((?!_next/static|_next/image|favicon.ico|sitemap.xml|robots.txt).*)'],
  }

CRITICAL constraints:
  - NEVER use getSession() — only getClaims() validates JWT signature
  - NEVER import cookies from 'next/headers' in middleware — use parseCookieHeader instead
  - Matcher MUST exclude _next/static and _next/image to prevent hundreds of getClaims() calls per page load
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → middleware | Unauthenticated requests must be blocked at middleware, not component level |
| JWT claims → route access | JWT must be validated (getClaims), not trusted from cookie value alone |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-00-09 | Spoofing | getSession() without signature validation | mitigate | middleware.ts uses getClaims() which validates JWT signature; getSession() forbidden |
| T-00-10 | Elevation of Privilege | Barber accessing owner routes | mitigate | Rule C in middleware redirects role=barber from /dashboard to /agenda |
| T-00-11 | Elevation of Privilege | Unauthenticated access to protected routes | mitigate | Rules A in middleware redirects no-claims requests to /entrar |
| T-00-12 | Information Disclosure | Middleware running on static files (performance + info leakage) | mitigate | Matcher excludes _next/static, _next/image, favicon — no getClaims() on static requests |
| T-00-SC | Tampering | npm/pip/cargo installs | accept | No new packages; uses already-installed @supabase/ssr |
</threat_model>
