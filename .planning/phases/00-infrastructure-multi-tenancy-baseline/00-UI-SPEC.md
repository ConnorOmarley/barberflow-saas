# Phase 0 — UI Design Contract

> Visual and interaction contract for Phase 0: Infrastructure & Multi-Tenancy Baseline.
> Generated by gsd-ui-researcher. All copy in pt-BR (Brazilian Portuguese).

---

## Scope

Phase 0 delivers exactly 5 UI surfaces — all auth-related. No data pages, no dashboards with
content. Only the structural shells for owner and barber route groups.

| Surface | Route (App Router) | Requirement |
|---------|-------------------|-------------|
| Owner signup | `/cadastro` | AUTH-01 |
| Owner login | `/entrar` | AUTH-02 |
| Password reset (request) | `/recuperar-senha` | AUTH-03 |
| Password reset (new password) | `/nova-senha` (callback route) | AUTH-03 |
| Barber invite acceptance | `/aceitar-convite` (callback route) | AUTH-05 |
| Owner dashboard shell | `/(owner)/dashboard` | AUTH-02, AUTH-06 |
| Barber dashboard shell | `/(barber)/agenda` | AUTH-06 |

The dashboard shells are empty route group containers — they render only a header with user
role badge and a signout button. No content until Phase 1.

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, inline field icon padding |
| sm | 8px | Between form label and input, between stacked inputs |
| md | 16px | Card internal padding, button horizontal padding |
| lg | 24px | Card padding (vertical), section gaps within auth card |
| xl | 32px | Auth card max-width inner margin, gap between card and logo |
| 2xl | 48px | Vertical centering offset from viewport top |
| 3xl | 64px | Not used in Phase 0 |

Exceptions:
- Touch targets for all buttons: minimum 44px height (mobile accessibility — Brazilian market
  is predominantly mobile)
- Auth card max-width: 400px on desktop, full-width with 16px horizontal margin on mobile

## Typography

All sizes in rem/px equivalents. Base: 16px = 1rem.

| Role | Size | Weight | Line Height | Usage in Phase 0 |
|------|------|--------|-------------|-----------------|
| Body | 14px (0.875rem) | 400 (regular) | 1.5 | Input placeholder, helper text, link text |
| Label | 14px (0.875rem) | 400 (regular) | 1.4 | Form field labels (`<Label>`) |
| Heading | 20px (1.25rem) | 600 (semibold) | 1.2 | Auth card title (e.g. "Entrar na conta") |
| Display | 28px (1.75rem) | 600 (semibold) | 1.15 | Brand name "BarberFlow" above auth card |

Font weights used: **400 (regular) and 600 (semibold) only.** No other weights are permitted
in Phase 0. Inter subset loads only these two weights.

## Color

Theme: dark professional. Barbershop-appropriate — not clinical white. Consistent with the
Brazilian barbershop premium market aesthetic.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0a0a0a` (near-black) | Page background, auth page body |
| Secondary (30%) | `#1a1a1a` (dark card) | Auth card background, dashboard shell header |
| Accent (10%) | `#d97706` (amber-600) | See reserved list below |
| Destructive | `#dc2626` (red-600) | Destructive actions only |
| Border | `#2a2a2a` | Input borders, card borders |
| Muted text | `#737373` | Placeholder text, helper text |
| Inverted text | `#fafafa` | Primary text on dark backgrounds |

Accent `#d97706` reserved for:
1. Primary CTA button background ("Criar conta", "Entrar na conta")
2. Focus ring on active form inputs
3. Link text for secondary actions ("Esqueci minha senha", "Voltar para login")
4. Role badge background in dashboard shell header (owner only)

Accent is NOT used for: borders, backgrounds, hover states of non-CTA elements, icons.

**shadcn CSS variable mapping** (set in `globals.css` after init):
```css
--background: 0 0% 4%;          /* #0a0a0a */
--card: 0 0% 10%;               /* #1a1a1a */
--primary: 38 92% 50%;          /* #d97706 amber */
--primary-foreground: 0 0% 4%;  /* dark text on amber button */
--destructive: 0 72% 51%;       /* #dc2626 */
--border: 0 0% 16%;             /* #2a2a2a */
--muted-foreground: 0 0% 45%;   /* #737373 */
--foreground: 0 0% 98%;         /* #fafafa */
```

## Visuals

Primary focal point: the amber primary CTA button is the dominant visual anchor on all auth screens.

All other interactive elements (secondary links, ghost buttons) are visually subordinate to
the amber CTA. The amber button's contrast against the dark card background ensures it draws
the eye immediately upon page load, guiding users to the primary action without distraction.

## Layout Contract

### Auth Pages (signup, login, password reset, invite acceptance)

```
Viewport: full height, dark background (#0a0a0a)
Layout: flex column, items centered, justify center
  └── Brand mark: "BarberFlow" Display/28px/semibold + scissor icon (lucide: Scissors)
      gap: 8px between icon and text
  └── Auth card: max-w-[400px], w-full, mx-4
      background: #1a1a1a
      border: 1px solid #2a2a2a
      border-radius: 12px (rounded-xl)
      padding: 32px (p-8)
      └── Card heading (Heading/20px/semibold)
      └── Card subheading (Body/14px/regular, muted text)
      └── Form fields (gap-4 between each field group)
      └── Primary CTA button (w-full, h-11, amber background)
      └── Secondary link (centered, Body/14px/regular, amber text)
```

### Dashboard Shells (owner, barber)

```

  └── Header: h-14, background #1a1a1a, border-bottom #2a2a2a
        └── Left: brand mark "BarberFlow" (Label/14px/semibold)
        └── Right: role badge + user email + signout button (ghost variant)
  └── Main: flex-1, background #0a0a0a
        └── Empty state placeholder (see Copywriting Contract)
```

## Interaction Contract

### Form Behavior

- Validation: client-side via React Hook Form + Zod, triggered on submit (not on blur for
  Phase 0 — reduces friction during initial auth)
- Field error: displayed below the input in Body/14px/destructive color, with a 4px top gap
- Submit button: disabled + shows loading spinner (lucide: Loader2, `animate-spin`) while
  awaiting Supabase response
- Success feedback: redirect (not toast) — auth pages redirect on success, no inline success
  messages needed in Phase 0

### Password Fields

- Show/hide toggle: lucide Eye / EyeOff icon button, positioned right-inside input (absolute
  position, right-3, vertically centered)
- Icon button: 32px touch target, no border, ghost variant

### Signout

- Signout button ("Sair") triggers immediately on click with no confirmation dialog or modal.
  Signout is a non-destructive, reversible action — the user can sign back in at any time.
  No confirmation is required.

### Error Handling

All Supabase Auth errors surface via `<Alert variant="destructive">` above the form submit
button. Single alert replaces itself on each new error (no stacking).

| Supabase Error | User-facing copy (pt-BR) |
|----------------|--------------------------|
| Invalid credentials | "Email ou senha incorretos. Verifique seus dados e tente novamente." |
| Email not confirmed | "Confirme seu email antes de entrar. Verifique sua caixa de entrada." |
| Email already in use | "Este email já está cadastrado. Tente entrar ou recuperar sua senha." |
| Invalid invite token | "Este convite expirou ou já foi utilizado. Solicite um novo convite ao dono da barbearia." |
| Rate limited | "Muitas tentativas. Aguarde alguns minutos e tente novamente." |
| Generic/unknown | "Ocorreu um erro inesperado. Tente novamente ou entre em contato com o suporte." |

### Route Protection

- Unauthenticated user accessing `/(owner)/dashboard` or `/(barber)/agenda`: redirect to
  `/entrar` (handled in middleware.ts, not component-level)
- Authenticated user accessing `/entrar` or `/cadastro`: redirect to role-appropriate
  dashboard (`/(owner)/dashboard` or `/(barber)/agenda`) based on JWT `role` claim
- Role mismatch (barber accessing owner route): redirect to `/(barber)/agenda`

## Accessibility Contract

- All form inputs have associated `<Label>` with `htmlFor` matching input `id`
- Error messages use `role="alert"` (shadcn `<Alert>` does this automatically)
- Password show/hide button has `aria-label="Mostrar senha"` / `aria-label="Ocultar senha"`
- Primary CTA loading state has `aria-busy="true"` and `aria-label="Carregando..."` during
  submission
- Color contrast: `#fafafa` on `#1a1a1a` = 12.6:1 (exceeds WCAG AA 4.5:1)
- Color contrast: amber `#d97706` on `#0a0a0a` = 5.2:1 (passes WCAG AA for large text/buttons)
- Minimum touch target: 44px height on all interactive elements
