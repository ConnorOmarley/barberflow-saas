FILE: scripts/check-rls.sh
Content: Bash script (#!/usr/bin/env bash, set -euo pipefail).
Purpose: Execute the CI check against the linked remote Supabase project.
Logic:
  1. Run: COUNT=$(supabase db query "SELECT COUNT(*) FROM pg_tables WHERE schemaname = 'public' AND rowsecurity = false;" --output plain 2>/dev/null | tail -1 | tr -d ' \r')
  2. If COUNT is not "0": echo "FAIL: $COUNT tables in public schema have RLS disabled" and exit 1
  3. If COUNT is "0": echo "PASS: All public tables have RLS enabled ($COUNT tables checked)" and exit 0
  4. Handle edge case: if COUNT is empty or non-numeric, echo "ERROR: Could not query database — is supabase linked?" and exit 2.
Make the script executable: chmod +x scripts/check-rls.sh.

FILE: tests/rls_isolation.sql
Content: SQL test that verifies cross-tenant isolation. Header comment explains this is run manually against the Supabase project to verify that a JWT with barbershop_id=A cannot see rows belonging to barbershop_id=B.
Include a clear usage comment: "Run via: psql $DATABASE_URL -f tests/rls_isolation.sql"
The test sets up two hypothetical barbershop UUIDs and asserts that selecting from public.barbershops with a JWT claim for one UUID does not return a row with a different UUID. Since we cannot set JWT claims in plain SQL outside Supabase auth context, the test is structured as:
  -- Step 1: Verify RLS is enabled on all tables
  DO $$ BEGIN
    ASSERT (SELECT COUNT(*) FROM pg_tables WHERE schemaname='public' AND rowsecurity=false) = 0,
           'FAIL: Tables without RLS found';
    RAISE NOTICE 'PASS: All public tables have RLS enabled';
  END $$;
  -- Step 2: Verify barbershop_id columns exist on tenant tables
  DO $$ BEGIN
    ASSERT (SELECT COUNT(*) FROM information_schema.columns WHERE table_schema='public' AND table_name='clients' AND column_name='barbershop_id') = 1,
           'FAIL: barbershop_id missing from clients';
    ASSERT (SELECT COUNT(*) FROM information_schema.columns WHERE table_schema='public' AND table_name='profiles' AND column_name='barbershop_id') = 1,
           'FAIL: barbershop_id missing from profiles';
    RAISE NOTICE 'PASS: barbershop_id columns present on tenant tables';
  END $$;

FILE: tests/rls_clients.sql
Content: SQL test that verifies the clients table schema and RLS policies. Header comment: "Verifies AUTH-07: clients table exists with whatsapp_opt_in field, anon insert policy exists."
  DO $$ BEGIN
    -- Verify clients table exists
    ASSERT (SELECT COUNT(*) FROM information_schema.tables WHERE table_schema='public' AND table_name='clients') = 1,
           'FAIL: clients table not found';
    -- Verify whatsapp_opt_in column exists (LGPD requirement)
    ASSERT (SELECT COUNT(*) FROM information_schema.columns WHERE table_schema='public' AND table_name='clients' AND column_name='whatsapp_opt_in') = 1,
           'FAIL: whatsapp_opt_in column not found in clients';
    -- Verify opt_in_timestamp column exists
    ASSERT (SELECT COUNT(*) FROM information_schema.columns WHERE table_schema='public' AND table_name='clients' AND column_name='opt_in_timestamp') = 1,
           'FAIL: opt_in_timestamp column not found in clients';
    -- Verify anon_client_insert policy exists
    ASSERT (SELECT COUNT(*) FROM pg_policies WHERE schemaname='public' AND tablename='clients' AND policyname='anon_client_insert') = 1,
           'FAIL: anon_client_insert policy not found on clients';
    RAISE NOTICE 'PASS: clients table and LGPD fields verified';
  END $$;
