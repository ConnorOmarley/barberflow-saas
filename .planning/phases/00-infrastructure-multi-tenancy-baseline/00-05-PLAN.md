  <action>
Replace the placeholder in src/app/auth/confirm/route.ts with the full implementation.

This is a Route Handler (not a 'use client' component). No 'use client' directive.

Imports:
  - createClient from '@/lib/supabase/server'
  - type NextRequest from 'next/server'
  - NextResponse from 'next/server'

FUNCTION: export async function GET(request: NextRequest)

Logic:
  1. Extract URL params: const { searchParams } = new URL(request.url)
  2. const token_hash = searchParams.get('token_hash')
  3. const type = searchParams.get('type') as 'email' | 'recovery' | 'invite' | null
  4. const next = searchParams.get('next') ?? '/'

  5. If token_hash AND type are present:
     const supabase = await createClient()
     const { error } = await supabase.auth.verifyOtp({ type, token_hash })
     If NO error:
       - If type === 'invite': redirect to /aceitar-convite
       - Otherwise: redirect to next (e.g., /dashboard or /nova-senha)
     If error: fall through to error redirect

  6. Error fallback: return NextResponse.redirect(new URL('/entrar?erro=link-invalido', request.url))

IMPORTANT: The redirect URLs must be absolute. Use new URL(path, request.url) to build them from the request origin, so they work in both localhost and production.

Note for /nova-senha flow: when type='recovery' and next='/nova-senha', the verifyOtp() call establishes an authenticated session for the user. The /nova-senha page then calls supabase.auth.updateUser({ password: newPassword }) to set the new password.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User input → Zod validation | Email/password from form fields must be validated before Supabase auth calls |
| token_hash in URL → verifyOtp | PKCE code from email links must be single-use and expire |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-00-13 | Spoofing | Invalid credentials on /entrar | mitigate | signInWithPassword() rejects invalid creds; pt-BR error shown; no credential hints |
| T-00-14 | Elevation of Privilege | PKCE token_hash replay | mitigate | verifyOtp() codes are single-use and expire in 5 minutes; Supabase enforces this |
| T-00-15 | Tampering | Unvalidated form input | mitigate | Zod schema validates email format and password min length before any Supabase call |
| T-00-16 | Information Disclosure | Supabase raw error messages | mitigate | All errors mapped to generic pt-BR messages; no raw Supabase error text shown to user |
| T-00-SC | Tampering | npm/pip/cargo installs | accept | No new packages; all dependencies installed in Plan 01 |
</threat_model>
