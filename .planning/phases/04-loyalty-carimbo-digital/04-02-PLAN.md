HELPER `getAuthContext` (copiar de barbers.ts linhas 9-36 — obrigatório por MEMORY.md):
Lê barbershop_id de `profiles` via `adminClient`, não do JWT diretamente. Retorna `{ userId: string; barbershopId: string } | { error: string }`.

FUNÇÃO `getLoyaltyRule` (exportada):
- Chama `getAuthContext()`.
- Usa `adminClient` para buscar `loyalty_rules` por `barbershop_id` com `.maybeSingle()`.
- Retorna `{ data: LoyaltyRule | null } | { error: string }`. Usar tipo local inline (não importar de database.types para evitar dependência circular com plano 04-03).

FUNÇÃO `upsertLoyaltyRule` (exportada):
- Recebe `{ stamps_required: number; reward_description: string }`.
- Chama `getAuthContext()`.
- Valida: `stamps_required` entre 1 e 100; `reward_description` não-vazia, máximo 200 chars.
- Usa `adminClient.from('loyalty_rules').upsert({ barbershop_id: ctx.barbershopId, stamps_required, reward_description, is_active: true }, { onConflict: 'barbershop_id' }).select('id').single()`.
- Retorna `{ data: { id: string } } | { error: string }`.
- Chama `revalidatePath('/dashboard/fidelidade')` antes de retornar sucesso.

FUNÇÃO `createStampOnComplete` (NÃO exportada — uso interno):
- Assinatura: `async function createStampOnComplete(appointmentId: string, barbershopId: string): Promise<void>`
- Usa `adminClient` para buscar `client_id` do appointment: `.from('appointments').select('client_id').eq('id', appointmentId).single()`.
- Se `!appt?.client_id`, retorna silenciosamente.
- Insere em `loyalty_stamps`: `{ barbershop_id: barbershopId, client_id: appt.client_id, appointment_id: appointmentId }`.
- Usa `.insert({...})` sem `.select()` (não precisamos do retorno).
- Trata `error.code === '23505'` como no-op (unique_violation = stamp já existe).
- Qualquer outro erro: `console.error('[loyalty] stamp insert error:', error.message)` — nunca throw.
- Envolver tudo em try/catch: `console.error('[loyalty] createStampOnComplete error:', err)`.

FUNÇÃO `redeemLoyaltyCard` (exportada — implementação mínima, lista completa em plano 04-03):
- Recebe `clientId: string`.
- Chama `getAuthContext()`.
- Stub de retorno para compilar: busca active stamp count, valida >= stamps_required, insere em `loyalty_redemptions` com `{ barbershop_id, client_id: clientId, redeemed_by: ctx.userId, stamps_used: activeCount }`.
- Lógica de contagem: buscar MAX(loyalty_redemptions.created_at) para este client; COUNT stamps com created_at > esse timestamp (ou '1970-01-01' se nunca resgatou).
- Retorna `{ success: true; stampsUsed: number } | { error: string }`.
- Chama `revalidatePath('/dashboard/fidelidade')`.
- Envolver tudo em try/catch.

IMPORTANTE: Cada função exportada deve estar envolvida em try/catch retornando `{ error: string }` em caso de exceção — nunca throw para o caller.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| updateAppointmentStatus → createStampOnComplete | barbershop_id passado como parâmetro após já ter sido validado do JWT — não há superfície de injeção |
| upsertLoyaltyRule → loyalty_rules | barbershop_id lido exclusivamente de profiles via adminClient — owner não pode forçar escrita em outra barbearia |
| loyalty-config.tsx → upsertLoyaltyRule | Formulário envia apenas stamps_required e reward_description — barbershop_id nunca é parâmetro do cliente |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-04 | Tampering | createStampOnComplete barbershop_id | mitigate | barbershop_id passa pelo JWT gate de updateAppointmentStatus antes de chegar ao helper |
| T-04-05 | Denial of Service | stamp fire-and-forget | accept | Falha silenciosa é intencional (Pitfall 2 da RESEARCH) — stamp perdido é recuperável por admin |
| T-04-06 | Elevation of Privilege | upsertLoyaltyRule | mitigate | barbershop_id vem de profiles via adminClient — nunca do payload do formulário |
| T-04-07 | Spoofing | getLoyaltyRule em page.tsx | mitigate | Server Component usa createClient() com sessão autenticada; barbershop_id do JWT já foi validado pelo middleware |
