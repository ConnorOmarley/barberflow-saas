HEADER obrigatório (copiar padrão de 20260531000001_phase1_schema.sql linhas 1-9):
```
-- ============================================================
-- BarberFlow Phase 4 — Loyalty Schema
-- Migration: 20260603000001_phase4_schema.sql
--
-- MULTI-TENANCY CONTRACT:
--   Every table has ENABLE ROW LEVEL SECURITY immediately after CREATE TABLE.
--   All RLS policies read barbershop_id from JWT app_metadata (not user_metadata).
--   Cast is always explicit: (auth.jwt() -> 'app_metadata' ->> 'barbershop_id')::UUID
-- ============================================================
```

SEÇÃO A — `loyalty_rules` (uma regra por barbearia):
- Campos: id UUID PK, barbershop_id UUID NOT NULL UNIQUE REFERENCES barbershops ON DELETE CASCADE, stamps_required SMALLINT NOT NULL DEFAULT 10 CHECK (BETWEEN 1 AND 100), reward_description TEXT NOT NULL DEFAULT 'Corte grátis', is_active BOOLEAN NOT NULL DEFAULT true, created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(), updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
- UNIQUE(barbershop_id) — constraint nomeada `loyalty_rules_barbershop_id_key` via UNIQUE na definição da coluna
- RLS: ENABLE ROW LEVEL SECURITY + policy "tenant_loyalty_rules_all" FOR ALL TO authenticated USING/WITH CHECK com cast JWT padrão

SEÇÃO B — `loyalty_stamps` (um carimbo por agendamento concluído, append-only):
- Campos: id UUID PK, barbershop_id UUID NOT NULL REFERENCES barbershops ON DELETE CASCADE, client_id UUID NOT NULL REFERENCES clients ON DELETE CASCADE, appointment_id UUID NOT NULL REFERENCES appointments ON DELETE CASCADE, created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
- UNIQUE INDEX `loyalty_stamps_appointment_id_idx` ON (appointment_id) — idempotência
- INDEX `loyalty_stamps_client_barbershop_idx` ON (barbershop_id, client_id, created_at) — query de contagem ativa
- RLS: ENABLE ROW LEVEL SECURITY + policy "tenant_loyalty_stamps_all" usando barbershop_id direto

SEÇÃO C — `loyalty_redemptions` (um resgate por cartela completa):
- Campos: id UUID PK, barbershop_id UUID NOT NULL REFERENCES barbershops ON DELETE CASCADE, client_id UUID NOT NULL REFERENCES clients ON DELETE CASCADE, redeemed_by UUID NOT NULL REFERENCES auth.users(id), stamps_used SMALLINT NOT NULL (snapshot de stamps_required no momento do resgate), notes TEXT NULL, created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
- INDEX `loyalty_redemptions_client_barbershop_idx` ON (barbershop_id, client_id, created_at DESC)
- RLS: ENABLE ROW LEVEL SECURITY + policy "tenant_loyalty_redemptions_all" usando barbershop_id direto
- NÃO usar ON DELETE CASCADE na FK de loyalty_rules — resgates devem sobreviver a mudanças de regra

Não adicionar campo `stamped_at` em loyalty_stamps — usar `created_at` como timestamp do carimbo (conforme RESEARCH.md schema design).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Supabase Auth JWT → RLS | barbershop_id extraído do app_metadata pelo Postgres; nunca passado diretamente pelo cliente |
| adminClient (service role) → DB | Bypass de RLS intencional para writes privilegiados — nunca exposto ao browser bundle |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | loyalty_stamps.appointment_id | mitigate | UNIQUE INDEX loyalty_stamps_appointment_id_idx previne double-stamp no nível do banco |
| T-04-02 | Elevation of Privilege | loyalty_rules RLS policy | mitigate | Policy usa cast JWT padrão do projeto — mesmo padrão auditado nas fases anteriores |
| T-04-03 | Spoofing | loyalty_redemptions.redeemed_by | mitigate | FK referencia auth.users(id) — não pode ser forjado pelo cliente; Server Action lê userId do JWT |
| T-04-SC | Tampering | npm/pip/cargo installs | accept | Nenhum pacote novo instalado neste plano — apenas DDL SQL e codegen CLI |
</threat_model>
