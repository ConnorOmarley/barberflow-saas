FUNÇÃO `sendWhatsAppConfirmation(appointmentId: string)`:
Retorno: `Promise<{ success: true } | { error: string }>`

Lógica interna (executar nesta ordem):
1. Criar `admin = createAdminClient()`
2. Buscar appointment com joins em uma única query:
   ```
   admin.from('appointments').select(`
     id,
     start_time,
     barbershops!inner(id, name, whatsapp_notify_confirmation, timezone),
     clients!inner(id, full_name, whatsapp_number, whatsapp_opt_in),
     services!inner(name),
     barbers!inner(name)
   `).eq('id', appointmentId).single()
   ```
3. Se erro ou sem resultado: return `{ error: 'Agendamento não encontrado' }`
4. Guard LGPD: `if (!appt.clients.whatsapp_opt_in) return { success: true }` — silent no-op, nunca logar como erro
5. Guard feature flag: `if (!appt.barbershops.whatsapp_notify_confirmation) return { success: true }`
6. Graceful no-op de template: `if (!process.env.TWILIO_TEMPLATE_CONFIRMATION_SID) { console.warn('[whatsapp] TWILIO_TEMPLATE_CONFIRMATION_SID não configurado — no-op'); return { success: true } }`
7. Idempotência: verificar `whatsapp_message_log` para (appointment_id, message_type='confirmation', status='sent') — se encontrar, return `{ success: true }`
8. Formatar data/hora no timezone da barbearia com `toLocaleDateString`/`toLocaleTimeString` pt-BR — usar `appt.barbershops.timezone`
   - `dateStr`: `{ timeZone, weekday: 'long', day: 'numeric', month: 'long' }`
   - `timeStr`: `{ timeZone, hour: '2-digit', minute: '2-digit' }`
9. Chamar Twilio:
   ```typescript
   const twilioClient = createTwilioClient()
   const message = await twilioClient.messages.create({
     contentSid: process.env.TWILIO_TEMPLATE_CONFIRMATION_SID!,
     contentVariables: JSON.stringify({
       '1': appt.clients.full_name,
       '2': appt.barbershops.name,
       '3': appt.services.name,
       '4': appt.barbers.name,
       '5': dateStr,
       '6': timeStr,
     }),
     from: TWILIO_WHATSAPP_FROM,
     to: `whatsapp:${appt.clients.whatsapp_number}`,
   })
   ```
   NÃO passar `body` junto com `contentSid` — são mutualmente exclusivos (Pitfall 3 do RESEARCH).
10. INSERT em `whatsapp_message_log`:
    ```typescript
    await admin.from('whatsapp_message_log').insert({
      barbershop_id: appt.barbershops.id,
      appointment_id: appointmentId,
      client_id: appt.clients.id,
      message_type: 'confirmation',
      twilio_sid: message.sid,
      status: 'sent',
    })
    ```
11. return `{ success: true }`
12. Envolver tudo em try/catch — catch retorna `{ error: err instanceof Error ? err.message : 'Erro inesperado' }` e loga `console.error('[whatsapp] sendWhatsAppConfirmation error:', err)`

FUNÇÃO `updateWhatsAppSettings(data)` (exportada):
Parâmetros: `{ whatsapp_notify_confirmation: boolean, whatsapp_notify_reminder: boolean, whatsapp_reminder_hours: number }`
Retorno: `Promise<{ success: true } | { error: string }>`

Lógica:
1. `ctx = await getAuthContext()` — se `'error' in ctx`, return ctx
2. Validar: `if (data.whatsapp_reminder_hours < 1 || data.whatsapp_reminder_hours > 168) return { error: 'Horas de lembrete deve ser entre 1 e 168' }`
3. `admin = createAdminClient()`
4. `admin.from('barbershops').update({ whatsapp_notify_confirmation: data.whatsapp_notify_confirmation, whatsapp_notify_reminder: data.whatsapp_notify_reminder, whatsapp_reminder_hours: data.whatsapp_reminder_hours, updated_at: new Date().toISOString() }).eq('id', ctx.barbershopId)`
5. Se erro: return `{ error: error.message }`
6. `revalidatePath('/dashboard/configuracoes')`
7. return `{ success: true }`
8. Envolver em try/catch padrão.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| appointments.ts (servidor) → whatsapp.ts (servidor) | `appointmentId` passado como parâmetro; whatsapp.ts busca todos os dados via adminClient — cliente nunca controla `barbershop_id` nem `whatsapp_opt_in` |
| whatsapp.ts → Twilio API | Credenciais em variáveis de ambiente server-only; nunca expostas ao browser |
| whatsapp.ts → whatsapp_message_log | INSERT via adminClient com `barbershop_id` lido do DB (não do cliente) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-04 | Tampering | LGPD: envio sem opt-in | mitigate | Guard `if (!appt.clients.whatsapp_opt_in) return { success: true }` é a primeira verificação após busca do appointment |
| T-05-05 | Information Disclosure | `src/lib/twilio.ts` importado em 'use client' | mitigate | Arquivo sem `'use client'`; importação em Client Components causaria erro de build (process.env server-only) |
| T-05-06 | Tampering | Duplicate WhatsApp send | mitigate | Pre-check em `whatsapp_message_log` antes de chamar Twilio + UNIQUE INDEX no banco como fallback |
| T-05-07 | Spoofing | `barbershop_id` controlado pelo cliente | mitigate | `barbershop_id` nunca aceito como parâmetro — lido de `appt.barbershops.id` via adminClient query |
| T-05-08 | Denial of Service | Twilio failure bloqueia status update | mitigate | `void sendWhatsAppConfirmation()` (fire-and-forget) — exceção em whatsapp.ts nunca propaga para caller |
