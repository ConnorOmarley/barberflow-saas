Criar o diretório `supabase/functions/send-reminders/` e o arquivo `index.ts`.

ATENÇÃO: Esta é a primeira Edge Function do projeto. Usar Deno runtime, NÃO Node.js.
- Todas as variáveis de ambiente: `Deno.env.get('VAR')!` (nunca `process.env`)
- Import do supabase-js: `import { createClient } from 'https://esm.sh/@supabase/supabase-js@2'`
- NÃO usar `import twilio from 'twilio'` — usar fetch com Basic auth (Deno + twilio npm = risco de incompatibilidade)

ESTRUTURA DO ARQUIVO:

1. Imports e env vars no topo:
```typescript
import { createClient } from 'https://esm.sh/@supabase/supabase-js@2'

const SUPABASE_URL = Deno.env.get('SUPABASE_URL')!
const SERVICE_ROLE_KEY = Deno.env.get('SUPABASE_SERVICE_ROLE_KEY')!
const TWILIO_ACCOUNT_SID = Deno.env.get('TWILIO_ACCOUNT_SID') ?? ''
const TWILIO_AUTH_TOKEN = Deno.env.get('TWILIO_AUTH_TOKEN') ?? ''
const TWILIO_FROM = Deno.env.get('TWILIO_WHATSAPP_FROM') ?? ''
const REMINDER_TEMPLATE_SID = Deno.env.get('TWILIO_TEMPLATE_REMINDER_SID') ?? ''

const supabase = createClient(SUPABASE_URL, SERVICE_ROLE_KEY)
```

2. Helper `sendWhatsAppREST(to, contentSid, variables)`:
Chamar Twilio Messages API via fetch com Basic auth. Ver Pattern 3 do RESEARCH.md para implementação completa (URLSearchParams, header 'Authorization': 'Basic ' + btoa(...), verificação !resp.ok).
- Retornar o Twilio SID (string) se bem-sucedido
- Lançar Error se resp.ok for false (mensagem do campo `data.message ?? resp.status`)

3. `Deno.serve(async (_req) => { ... })`:

LÓGICA PRINCIPAL:

a. Graceful no-op se template não configurado:
```typescript
if (!REMINDER_TEMPLATE_SID || !TWILIO_ACCOUNT_SID) {
  console.warn('[reminders] TWILIO_TEMPLATE_REMINDER_SID ou TWILIO_ACCOUNT_SID não configurados — no-op')
  return new Response(JSON.stringify({ sent: 0, skipped: 0 }), {
    headers: { 'Content-Type': 'application/json' },
  })
}
```

b. Query: appointments CONFIRMED com joins em barbershops (whatsapp_notify_reminder=true), clients (whatsapp_opt_in=true), dentro de uma janela de 168h a partir de agora:
```typescript
const { data: appointments, error } = await supabase
  .from('appointments')
  .select(`
    id,
    start_time,
    barbershops!inner(id, name, timezone, whatsapp_notify_reminder, whatsapp_reminder_hours),
    clients!inner(id, full_name, whatsapp_number, whatsapp_opt_in),
    services!inner(name),
    barbers!inner(name)
  `)
  .eq('status', 'CONFIRMED')
  .eq('barbershops.whatsapp_notify_reminder', true)
  .eq('clients.whatsapp_opt_in', true)
  .gte('start_time', new Date().toISOString())
  .lte('start_time', new Date(Date.now() + 168 * 3_600_000).toISOString())
```

c. Para cada appointment no loop:
  - Verificar janela per-barbershop: `apptTime > now + windowMs` → skipped++; continue
  - Checar idempotência em `whatsapp_message_log` para (appointment_id, message_type='reminder', status='sent') → se existir: skipped++; continue
  - Formatar dateStr e timeStr em pt-BR com timezone da barbearia (mesmo padrão de whatsapp.ts do plano 05-02)
  - Chamar `sendWhatsAppREST` com ContentVariables `{ '1': full_name, '2': barbershop.name, '3': service.name, '4': barber.name, '5': dateStr, '6': timeStr }`
  - Tratar em try/catch interno: capturar status ('sent' | 'failed') e errorMsg
  - SEMPRE fazer INSERT em `whatsapp_message_log` independente de sucesso ou falha (ver RESEARCH Pitfall 7 — logar antes garante que timeout não cause reenvio):
    ```typescript
    await supabase.from('whatsapp_message_log').insert({
      barbershop_id: appt.barbershops.id,
      appointment_id: appt.id,
      client_id: appt.clients.id,
      message_type: 'reminder',
      twilio_sid: twilioSid,
      status: sendStatus,
      error_message: errorMsg,
    })
    ```
  - `.then(() => {})` no INSERT para não bloquear próxima iteração

d. Retornar `{ sent, skipped }` como JSON com status 200.
e. Envolver o bloco principal em try/catch — catch retorna status 500 com `{ error: String(err) }`.

Ver o exemplo completo "Edge Function: send-reminders" no arquivo 05-RESEARCH.md para referência de implementação detalhada.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pg_cron → Edge Function | pg_cron chama via net.http_post com apikey do vault; Edge Function usa SERVICE_ROLE_KEY para acesso completo ao banco |
| Edge Function → Twilio API | Basic auth com TWILIO_ACCOUNT_SID:TWILIO_AUTH_TOKEN; secrets não expostos em logs |
| Edge Function → whatsapp_message_log | INSERT via SERVICE_ROLE_KEY (bypassa RLS) — correto para background job que não tem usuário JWT |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-12 | Tampering | LGPD: lembrete sem opt-in | mitigate | Query filtra `.eq('clients.whatsapp_opt_in', true)` — appointments de clientes sem opt-in nunca entram no loop |
| T-05-13 | Tampering | Lembrete duplicado | mitigate | Pre-check de `whatsapp_message_log` por (appointment_id, 'reminder', 'sent') antes de chamar Twilio; UNIQUE INDEX como fallback |
| T-05-14 | Spoofing | pg_cron sem autenticação | mitigate | Opção A (Dashboard) usa token de service role via Supabase runtime; Opção B usa vault secrets para apikey header |
| T-05-15 | Denial of Service | Timeout de Edge Function em batch grande | accept | MVP scale: < 50 appointments/hora esperado. Mitigação futura: chunking ou Supabase Queues. INSERT antes da chamada Twilio previne reenvio se timeout ocorrer. |
| T-05-16 | Information Disclosure | TWILIO_AUTH_TOKEN em logs | mitigate | Secrets via `Deno.env.get()` — nunca logar os valores das variáveis; Basic auth header construído em memória |
| T-05-SC | Tampering | npm/pip/cargo installs | accept | Edge Function usa apenas imports ESM (https://esm.sh/) — sem npm install; não aplicável |
</threat_model>
